# Dokumentasi dan Kontrak Host

**Cabang Fitur:** feature-documentation-core-alignment

## Dokumentasi terstruktur

Info, Penggunaan, dan Teknis menjadi keluarga dokumen terlokalisasi lengkap yang dideklarasikan manifes modul. Pengantar pengguna, prosedur praktis, serta kontrak API/konfigurasi memiliki tampilan terpisah. Pemeriksaan ketat susunan, referensi, dan nama berkas berjalan dalam pengujian mandiri serta CI. Tautan sumber mengikuti cabang bawaan; label tautan changelog memakai referensi komit singkat.

## Diagnostik gateway

Diagnostik runtime memakai gerbang logging host beserta kebijakan keluarannya. Laporan perintah memakai aliran terminal, dan pemeriksaan konsol native mencakup JavaScript modul, alias, serta akses terhitung. Kepemilikan penyedia, otorisasi, dan identitas penyelesaian tutorial tetap dipertahankan.

## Laporan untuk Layar Ringkas

Baris laporan memakai tampilan ringkas Composer untuk menempatkan bilah peristiwa di bawah label dan jumlah. Total dan filter dapat berpindah baris; tabel dengan proporsi kolom tetap membungkus stempel waktu pada layar sempit sambil mempertahankan pengaturan tipografi dan tema host.

## Nama binding deskriptif

Validasi nama berbasis pohon sintaks memeriksa deklarasi, ekspor, destrukturisasi, parameter waktu jalan dan tanda tangan tipe, properti parameter konstruktor, binding catch, impor, fungsi dan kelas bernama, binding enum dan namespace waktu jalan, serta anggota privat tanpa bergantung pada format. Pemindaian mencakup sumber, perkakas, pengujian, dan fixture tanpa pengecualian berkas atau daftar pelanggaran lama. Singkatan tidak jelas, bentuk jamak yang disingkat, pengganti bernomor, dan penggunaan binding yang diabaikan menggagalkan validasi. Istilah lazim seperti `args`, `db`, LDAP `dn`, HTTP `req`/`res`, `env`, `opts`, dan `params` tetap sah; glosarium menentukan kosakata lengkap. Pengecualian pendek lainnya adalah `_` yang tidak digunakan dan tidak diekspor, `id`, serta penghitung numerik `i`/`j`/`k` dengan pembaruan aritmetika yang sesuai. Koordinat dan ukuran memakai nama lokal deskriptif. API helper dan penyimpanan milik komponen memakai nama deskriptif langsung pada deklarasi, ekspor, impor, dan pemanggil; alias impor/ekspor yang hanya mengganti nama menggagalkan validasi. Konsumen harus memakai ekspor kanonis, bukan alias singkat. Kunci muatan publik, pengenal kapabilitas, dan identitas khusus tipe mempertahankan peran kontraknya. Manual teknis terlokalisasi, petunjuk kontribusi, versi modul, berkas kunci, dan hash paket diselaraskan.
