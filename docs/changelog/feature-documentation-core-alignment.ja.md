# 文書構成とホストの契約

**機能ブランチ:** feature-documentation-core-alignment

## 構造化した文書

Info、使用例、技術情報を、マニフェストで宣言する完全な多言語の文書一式にします。利用者向けの紹介、具体的な手順、現在の API と設定の契約を分けて説明します。構成、参照先、ファイル名の厳密な検証を独立したテストと CI で実行します。ソースファイルへのリンクは既定ブランチを参照し、変更履歴のコミットラベルは短い形式を使います。

## ゲートウェイの診断

実行時の診断はホストのログゲートウェイと出力方針に従います。コマンドの報告は端末出力を使い、モジュールの JavaScript では別名や動的な参照も含めてネイティブコンソールへのアクセスを検証します。プロバイダーの所有範囲、権限確認、ガイド完了の識別子を維持します。

## コンパクトな画面で読めるレポート

レポートの行は Composer のコンパクト表示を使い、イベントの棒を名前と件数の下に置きます。集計とフィルターは折り返し、列比率を固定したイベント表は狭い画面で日時を折り返して、ホストの文字とテーマの設定に従います。

## 役割が分かるバインディング名

構文木による名前検証は、書式に依存せず、宣言、エクスポート、分割代入、実行時と型シグネチャの引数、コンストラクターのパラメータープロパティ、catch のバインディング、インポート、名前付き関数とクラス、実行時の enum と名前空間、非公開メンバーを検証します。既存違反の除外やファイル別の例外を設けず、ソース、ツール、テスト、フィクスチャを走査します。不明瞭な省略名、省略語の複数形、番号付きの仮名、無視するバインディングの値の使用は検証に失敗します。`args`、`db`、LDAP の `dn`、HTTP の `req`/`res`、`env`、`opts`、`params` などの一般的な開発用語は有効で、用語集が完全な一覧を定義します。他の短い例外は未使用かつ非公開の `_`、`id`、対応する算術更新を持つ数値カウンター `i`・`j`・`k` です。座標と寸法には説明的なローカル名を使います。所有するヘルパーとストアの API は宣言、エクスポート、インポート、呼び出し元で説明的な名前を直接使用し、名前を変えるだけのインポート・エクスポート別名は検証に失敗します。利用側は省略別名ではなく正規のエクスポート名を使う必要があります。公開ペイロードのキー、機能の識別子、型専用の識別名は契約上の役割を維持します。各言語の技術文書、貢献指針、モジュールのバージョン、ロックファイル、パッケージのハッシュを同期します。
